## GitHub Pages

在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。工作流 `.github/workflows/pages.yml` 会把 `site/` 发布到 Pages；首次启用后，可在 Actions 中运行 **Deploy reading site to GitHub Pages**。

预期网址：https://byteleee.github.io/QTB/

后续提交到 `main` 会自动更新站点。正文为独立原创评论，不替代原著；说明性虚构场景不应当作真实史料。

## 个人阅读系统

全站首页提供统一书架（想读 / 在读 / 已完成）、继续阅读、本周计划和思想笔记。共 11 个主题、83 个已有阅读单元；《滔天洪水》当前只计为一篇完整导读，八期路线不冒充已完成正文。

- 将主题设为“在读”，默认每周安排 3 期，可选择 1–5 期。周一换周，多主题轮流安排；完成的任务保留在本周，不自动追加。调整状态/目标或点击重新安排才重算本周。
- 默认进入 `read.html?book=<theme>&episode=<number>` 统一阅读器。记录最后一期及正文进度，提供前后期、全辑目录、字号、夜读、浏览器语音和一问一答。主题原页和独立全文均保留，顶部统一链接回全站首页。
- 私人进度、回答仅保存在浏览器 `qtb-reading-system-v1`，不上传服务器，不写进 GitHub。支持完整 JSON 备份、确认后导入，以及 Markdown 思想笔记导出。换域名/浏览器/设备需手动导入。
- 已识别的旧主题笔记和已读记录在同域首次访问时迁入；新回答不会被旧笔记覆盖。旧版“最后打开”记录没有统一时间，首页续读从升级后实际打开的内容开始记录。原版页面继续阅读也会记录最近一期和进度。
- 语音依赖浏览器和设备提供的语音，支持短段播放、暂停/继续、停止、跳段、语速和声音选择。后台与锁屏连续播放无法保证；这不是离线音频播放器。

### 内容更新与验证

先运行各书自己的内容生成脚本，再运行 `python3 scripts/build-reading-system.py`。生成器复用现有正文和参考资料，更新 `site/reading-data/` 并为原页面补齐统一导航，重复运行不会重复注入。新增主题时在生成器的 `names` 与相应正文适配处登记。

`node --test tests/reading-system.test.cjs` 覆盖真实正文目录、旧记录迁移、备份归一化、跨周计划、已读撤销和导航覆盖。Pages 工作流在发布前重新生成目录并运行这些检查。
