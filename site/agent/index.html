第一篇 / EPISODE 01

它说“已经完成”，
事情就真的完成了吗？

原创讲述 · 约 10—13 分钟阅读 · 附 30—45 分钟实验
文中的程序员与开发现场为教学虚构；概念资料见页末参考书架。

一个不存在的文件

晚上九点，程序员准备关电脑。他刚给自己的阅读助手加了一个新功能：把讨论过的问题整理成笔记。他在对话框里输入：“把刚才关于有限理性的讨论保存下来，叫作 reading-note.txt。”几秒之后，屏幕上出现一行让人放心的文字：“已经为你保存好了。”

他打开文件夹。里面没有这个文件。他刷新一次，又搜索一次，仍然没有。模型没有报错，也没有迟疑。它甚至顺手补充了一句：“下次需要时可以继续查看。”如果只看聊天记录，这是一段成功的交互；如果看文件系统，这件事根本没有发生。

我们先不急着把问题归结为模型不诚实。退一步想：在这次交互里，究竟有什么东西拥有写入磁盘的能力？如果程序只把文字发送给模型，再把模型的文字显示到屏幕上，那么这条链路从头到尾都没有包含“写文件”这个动作。模型生成了描述结果的句子，应用却把它当成了结果本身。

这是一道很容易被流畅表达掩盖的边界。传统软件里，按钮上的“保存成功”通常来自某段执行逻辑。现在，一个语言模型也能写出这四个字。文字的外观一样，背后的证据却可能完全不同。

学习 Agent 的第一步，是学会追问：这句话背后，究竟发生了什么可检查的事情？

语言与世界之间

我们平常使用语言，经常是在协调行动。“我已经关门了”，说话的人既是报告者，也可能是关门的人。但在一个接入模型的应用里，生成语言、获得权限、执行操作、检查结果，往往属于不同的组件。把它们混在一起，就会出现一个能描述任何操作、却没有真正执行能力的助手。

可以把它想成一间小型办公室。有人理解要求，决定要做什么；有人拿着钥匙进入档案室；有人登记文件是否真的入库。这里的比喻只为帮助我们划清职责。模型并不是一个藏在服务器里的人，它输出的是文本或结构化的调用请求。真正访问磁盘、数据库和外部服务的，是我们提供的程序。

因此，所谓让模型“使用工具”，并不是模型突然长出了双手。开发者向它说明有哪些工具，每个工具能做什么、需要什么参数。模型提出一个调用请求，运行时检查这个请求，再执行对应函数。执行结果返回之后，模型才能根据新增的信息继续回应。

Anthropic 的《Building effective agents》把预先定义执行路径的工作流，与由模型动态决定过程和工具使用的 Agent 作了区分。这个区分能帮我们避免过早增加复杂度：如果任务始终是“收到内容，保存文件，返回路径”，普通函数和固定工作流已经足够。只有当下一步取决于执行中的发现，动态决策的价值才逐渐显现。

比如，研究助手先查本地笔记，发现只有结论没有出处，于是补查原始材料；发现两个来源矛盾，再向用户说明分歧。我们真正希望交给模型的，是在一定边界内选择下一步的能力，而不是对所有步骤无条件放手。

行动是怎样发生的

回到那个不存在的文件。如果要把功能修好，我们可以定义一个工具，叫作 save_note。它只接受两个参数：文件名和内容。模型收到用户要求后，不直接宣布成功，而是发出类似这样的请求：“调用 save_note，文件名为 reading-note.txt，内容为这段笔记。”

请求本身仍然不等于行动。程序要先检查：这个工具是否在允许列表里？参数是否符合格式？文件名是否越出了允许目录？这次操作会不会覆盖已有内容？只有通过检查，执行器才把内容写入文件。

完成写入之后，工具返回一个明确的结果：成功还是失败，保存在哪里，是否完成回读校验。如果写入失败，就返回错误类别和可理解的说明。模型拿到的是执行证据，而不是一个让它自由发挥的空白。

这条链路可以概括为：模型提出请求，程序校验并执行，工具返回观察结果，模型决定继续还是结束。工具调用可能不止一轮。但多轮并不是越多越好，每一轮都增加耗时、成本和出错的机会。我们需要设置调用次数或时间预算，在无法完成时有依据地停止。

特别要注意，屏幕里展示一段 JSON，也不意味着你的应用真的调用了工具。只有实际的调度代码把请求映射到允许的函数，动作才发生。接口外观可以很漂亮，执行边界却必须扎实。

给“完成”一个定义

在刚才的例子里，文件出现了，是否就可以结束？也不一定。文件可能写在错误目录里，内容可能为空，也可能把上一份笔记覆盖掉了。所谓验证，并不是一律再调用一次模型，说一句“请检查你的工作”。首先要问的，是这个任务有哪些可以直接检查的条件。

对于保存笔记，最简单的完成标准可以是：目标文件存在，内容与本次提交一致，路径位于指定目录，原有文件没有被意外覆盖。这些条件大多能由普通程序判定。我们没有必要把能确定计算的检查，全部交给一个不确定的判断过程。

但如果要求变成“这份笔记准确表达了作者的意思”，文件存在就不够了。此时需要对照来源，检查遗漏和歪曲，必要时由人审阅。系统层面的成功，与内容层面的质量，是两种不同的验收。一个工具返回成功，只能证明它承诺的那部分动作完成，不能替整条业务链路担保。

这也意味着，状态可以比成功和失败更细一点。比如“已写入，尚未核对内容”；“已生成草稿，等待确认后发送”；“操作超时，远端结果未知”。最后一种尤其重要：请求超时不意味着远端一定没有执行。盲目重试，可能生成两份相同记录，甚至发出两次通知。

所以，工程系统里的诚实，既依赖模型的表达，也依赖状态设计。如果程序只给模型两个选项，成功或失败，却把“不知道是否成功”藏起来，再好的提示词也很难完整表达事实。承认未知，需要系统先能够表示未知。

“完成”不是一句礼貌的收尾。它应该对应事先约定、事后能够检查的条件。

反馈，才是下一步的起点

现在，这位程序员再次输入保存笔记的要求。工具返回：“失败，目标文件已存在。”这一次，助手没有说保存好了。它告诉用户这个名字已经被使用，可以换个名字，或者在确认后覆盖。听起来，它似乎没有上次那么能干。但它终于开始根据世界的实际状态回应。

这就是反馈的价值。没有反馈时，系统只是沿着一种听起来合理的叙事前进；有了反馈，下一步至少有机会建立在新的事实之上。不过，反馈也可能不完整，工具描述也可能误导。一个请求被服务接收，不代表最终任务已经执行。设计工具时，我们必须把返回值的含义说清楚。

开发 Agent 很容易让人把注意力都放在“模型怎么想”上。我们会调整角色设定，让它更专业、更谨慎、更有条理。这些工作可能有帮助，但有时候，真正需要改变的是工具返回格式，是状态记录，是重复调用的处理方式，是一个清楚的终止条件。

对于有多年开发经验的人来说，这既陌生，又熟悉。陌生的是，某一部分控制流程由模型在运行时决定；熟悉的是，系统仍然需要接口、权限、错误处理、日志和验收。原有的工程经验没有失效，只是需要围绕一个带有不确定性的决策组件重新组织。

我们这一部系列要做的阅读研究助手，也从这里开始。今天它只需要可靠地保存一条笔记。以后，它会检索资料、比较观点、发现证据不足，再决定是否继续查找。每增加一项能力，我们都要问：这项能力有什么边界，失败怎样暴露，结果怎样验证？

当屏幕再次出现“已经完成”，我们不必完全依赖那句话让人放心的语气。我们可以打开记录，看见请求、执行、返回和验证。信任从这里有了一个具体的落点。

下一期，我们会继续追问：如果固定工作流就能可靠地完成很多任务，程序员为什么还要把一部分控制权交给模型？

动手实验 / 30—45 分钟

先做一把可靠的工具

本期先验证执行层，不需要 API Key。将下面的 Python 代码保存为 save_note.py，用 Python 3 运行。它只写入当前目录下的 notes 文件夹，拒绝覆盖，并在写入后检查内容。

from pathlib import Path
import json

ROOT = Path("notes").resolve()

def save_note(name: str, content: str) -> dict:
    if (not name or name in (".", "..")
            or "/" in name or "\\" in name
            or not name.endswith(".txt")):
        return {"ok": False, "error": "invalid_name"}
    if not content.strip():
        return {"ok": False, "error": "empty_content"}
    path = ROOT / name
    try:
        ROOT.mkdir(parents=True, exist_ok=True)
        # x 模式：文件存在时拒绝写入，避免静默覆盖
        with path.open("x", encoding="utf-8", newline="") as f:
            f.write(content)
        verified = path.read_text(encoding="utf-8") == content
        return {"ok": verified, "path": str(path),
                "verified": verified}
    except FileExistsError:
        return {"ok": False, "error": "already_exists"}
    except OSError as exc:
        return {"ok": False, "error": type(exc).__name__}

if __name__ == "__main__":
    result = save_note("reading-note.txt", "完成，需要证据。")
    print(json.dumps(result, ensure_ascii=False, indent=2))

这是受信任本地目录中的教学示例，不是生产级文件沙箱；未包含并发修改、符号链接攻击防护和模型工具调度。下一期起再逐步接入决策层。

展开自检提示

它是一个确定性的执行工具。它不会根据目标动态选择动作，也没有接收观察结果后继续决策的循环。接入模型后，仍应保留这些程序检查；不要因为模型“说参数安全”就跳过验证。
